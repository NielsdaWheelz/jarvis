## Persistence, recovery, and information flow

Every owner input receives a fresh isolated recaller before Main context is
rendered. The recaller returns unique row identities, not rewritten prose; host
code reopens the exact stored rows and supplies those exact rows as fallible
evidence. Candidate and selected identities plus bounded run counts and usage
are recorded in message trace. Prompts, memory copies, tool payloads, stable live
references, and private prose are not recorded there.

After each eligible settled owner-input group, a fresh isolated rememberer runs
in the background and yields to foreground work. Host code accepts only its
closed string list, rejects duplicate exact text and unmistakable private-key
blocks or known token prefixes without secret-bearing diagnostics, and appends
accepted raw rows plus all target `remembered_at` values in one transaction. A
valid empty list advances every target watermark while creating no memory or
action. Failure or cancellation advances none. No second memory store and no
action row are created.

The bounded startup/restart sweep selects only completed, unremembered
`role=owner` rows with eligible settlement outcomes. It groups by shared
run/checkpoint/conclusion identity, and uses the specified one-row fallback only
when old or damaged trace cannot establish grouping. Host action-resolution and
scheduled-wake rows are never targets. Failure summaries accept the complete
closed deployment batch ceiling of 100 rows without truncating or watermarking
the group. Shutdown and owner preemption wait through the short non-cancellable
database commit boundary, while derived embedding work remains cancellable.

Embedding calls use provider-runtime's OpenAI embedding port with a dedicated
embedding-only credential and a managed HTTP client with environment proxies
disabled. That credential is never placed in Codex content, child environment,
PostgreSQL, fixtures, or ordinary logs. Stable external references are stored
only as documented natural-language XML-like text. No XML schema, relationship
table, semantic category, confidence, salience, importance, authority,
validity, conflict, person, project, or procedure field was added.

Memory is explicitly evidence only. It cannot grant consent, approval, or
authority and cannot establish current connector state. Five deterministic
authority cases inject recalled claims for emailing, spending, secret
disclosure, destructive deletion, and consequential invitations. All five
effectful calls are rejected because Main's exact catalog remains read-only and
contains no memory tools.

## Accepted trade-offs

- Recall is foreground work before every owner-authored input. A cold recaller
  adds provider latency and tokens even when it validly selects no memory. The
  final paid cycles measured 15.392 seconds/37,568 tokens and 9.458
  seconds/25,372 tokens respectively, before Main work.
- The qualified recaller always performs a fixed first hybrid lexical/semantic
  search. Relevant summaries or a missing direct answer trigger one focused
  reformulation, and selected-summary continuation can require opening every
  raw lineage source. This explicit procedure improved compactness and lineage
  correctness, but it adds predictable embedding/database work plus provider
  turns even when an early candidate looks sufficient.
- Every stored memory and semantic search query is disclosed to the metered
  OpenAI embedding endpoint under the embedding-only project credential. The
  credential cannot generate, is never given to Codex, and the endpoint still
  receives that bounded text.
- Embedding availability is not a commit dependency. During provider outages,
  raw memory is permanent with `embedding = null`; lexical retrieval works and
  bounded backfill retries later. Semantic recall can therefore temporarily be
  incomplete.
- Raw memory grows indefinitely and cannot be deleted in v1. There is no
  redaction or forgetting operation. Storage, FTS indexes, exact vector scans,
  and future embedding rebuild costs grow with the permanent corpus.
- Exact pgvector cosine scans are linear and have no approximate index. This is
  the correct one-user starting point and avoids unmeasured recall loss, but
  latency will grow with corpus size. An ANN index requires measured need and a
  later explicit change.
- Four GIN expression indexes make both linguistic stemming and exact-token
  behavior independently available across both memory tables. They consume
  additional storage and write work for derived search state.
- Memory tools permit up to eight serial calls and large but finite aggregate
  output. Difficult recall can consume multiple provider turns and up to the
  internal role's 262,144-byte newly rendered context boundary; pathological
  cases stop boundedly rather than return an unbounded corpus.
- Remembering normally yields to foreground input. The short host-owned atomic
  memory/watermark commit is deliberately non-cancellable once entered, so a
  foreground arrival or shutdown can wait briefly for transaction integrity.
- The product-acceptance qualifier expands rolling capacity to exactly two
  one-owner cycles. It does not change production role plans or per-run limits,
  but qualification capacity is intentionally higher than one ordinary cycle.
- Provider session references, history, compaction, and cache remain disposable.
  Fresh isolated memory roles and Main cold bootstrap cost tokens, and local
  reference deletion does not establish deletion of provider-retained state.
- Paid recall behavior remains stochastic even with exact model, schema, role,
  plan, dependencies, and frozen cases. Post-normalization one-pass scores ranged
  from 2/17 to 17/17 as the general role procedure evolved, and attempts 9 and 10
  still showed zero-search noncompliance before the final 17/17 run. There is no
  automatic evaluator retry or claim that one paid pass eliminates future model
  variance. The evaluator rejects zero-search cases and production records the
  bounded search count, but production does not retry a valid closed empty
  terminal result solely because the role skipped its instructed search.
- Qualification databases and runtime directories may contain private
  canonical evidence. Automatic cleanup would conflict with append-only raw
  memory and could destroy failure evidence, so secure operator cleanup is
  required after sanitized recording.
- Provider-native event shapes and structured-output behavior remain mutable
  despite exact dependency, role, plan, and model pins. Exact pinning and the
  terminal-selection canaries constrain the qualified surface, but a later
  dependency change requires replay and may cold-bootstrap sessions.
- The inherited Linux-container Git package-index gap and Git-dependency audit
  limitation remain as recorded for Slice 2.
