## Delivered behavior

AutomaticWriteGate is a fresh isolated empty-plan kernel one-shot for every
validated model-proposed Write, before action creation. It uses
`InputProjectionPolicy(render_source_timestamps=False,
batch_as_of=BatchAsOfMode.on_request)`. Jarvis normally omits the projection
request and requests `render_batch_as_of=True` only when host policy finds a
relative-time validation need. The gate sees only current owner input and a
bounded normalized descriptor; it receives no memory, history, connector/Web
data, payload prose, rationale, credential, or execution authority. Failure or
denial creates no action.

Host policy classifies automatic versus approval-required work. Slice 5 executes
only unsent Gmail draft create/update, no-attendee writes on a configured and
verified owner-only calendar, and requested schedule create/cancel. Gmail send,
attendee-bearing work, and shared/unknown calendars fail closed with no external
effect because their approval path is Slice 6.

Gmail draft create carries action-derived `X-Jarvis-Effect-ID`. After ambiguous
create, each of three observations separated by `0`, `2`, and `8` seconds scans
at most five unfiltered unordered pages with eight IDs per page, at most forty
unique drafts, and at most forty `drafts.get(format=raw)` candidates. The entire
procedure is capped at 30 seconds, 16 MiB aggregate accepted response bytes, and
2 MiB per response. It never sends `q`. Evidence retains only absent/present/
invalid/unknown `nextPageToken` classification, never the token. One observed
exact header and normalized immutable-content match succeeds even with
incomplete pagination. Multiple matches, conflict, malformed/transient evidence,
incomplete no-match, and complete no-match settle terminal `uncertain`. No
absence result or list ordering ever authorizes another create. Explicit
provider rejection before acceptance remains an ordinary declared failure.

Calendar create uses an action-derived provider event ID. Create/update/delete
use exact get-and-compare reconciliation. Executor-entry attempts increment
immediately before actual executor entry, never for reconciliation reads.
Evidence-proven safe absence may repeat only within the immutable ceiling;
unresolved evidence becomes terminal `uncertain`. Startup reconciles executing
rows and creates one idempotent host action-resolution input when the original
model loop cannot receive the outcome.

`schedule.wake` create stores an immutable creation receipt while the action
remains queued. Cancel is its own gated action and can target only a queued
original. At the exact due instant, or on startup when overdue, a transaction
claims the action and creates one idempotent host wake with source
`schedule_wake`; completion writes a separate `wake_outcome`. The creation
receipt is replayable at every later state. A visible model response or
deterministic host fallback is required. No action or message polling framework,
lease, fifth table, quiet hours, connector monitor, or generic retry was added.

Owner-input recall now begins with a kernel-dispatched `InitialReadCall` to
`memory.search`, using the exact validated input and frozen recaller plan. Jarvis
does not pre-execute the read, create another budget, synthesize a model step, or
persist the observation. The kernel supplies lineage, shared budget, dispatch,
and typed projection. Commentary-encoded tool proposals cannot dispatch; only
the validated terminal structured result is consumed. The recaller may then
adaptively search/open as before.

## Accepted trade-offs

- AutomaticWriteGate adds one paid isolated model run, latency, and tokens to
  every proposed write. Its 5/5 safety and 3/3 usability result is evaluated
  behavior, not a proof against every future model error.
- Draft and verified owner-only no-attendee Calendar writes execute without an
  approval click after the gate. Gmail sending and consequential work do not.
- Gmail create recovery deliberately favors no duplicate effects over liveness.
  Its bounded unordered scan can miss an existing draft and surface terminal
  uncertainty requiring owner inspection. Conversely, one observed exact match
  is conclusive even if unscanned pages could contain another provider-side copy;
  the effect header and immutable-content comparison make that bounded choice
  explicit.
- Connector arguments and results are durable private database state. Ordinary
  logs remain metadata-only.
- Calendar's action-derived 128-bit provider ID has a negligible theoretical
  collision risk. Exact get-and-compare prevents overwrite or blind retry.
- The lifetime attempt ceiling is two, but the second entry is allowed only by
  evidence-proven safe absence. `uncertain` is terminal and requires inspection.
- One deployment owner and one advisory lock replace leases and a workflow
  service. This is intentionally unsuitable for active-active deployment.
- The process-local wake timer can drift or miss intervals while the service is
  down; startup makes overdue owner-requested wakes eligible. There is no durable
  job ledger or generic monitoring.
- Scheduled proactive runs consume paid model tokens and have only the read-only
  external plan. They intentionally do not receive recall.
- The initial recall search adds a deterministic read/embedding and foreground
  latency. Its bounded UTF-8 head/tail query can omit middle text from very long
  owner input; adaptive recaller calls can compensate.
- Recaller, Rememberer, and Dreamer add paid foreground/background tokens.
  Embeddings disclose accepted memory text to the metered embedding provider;
  vectors may remain null during outages. Raw memory remains append-only,
  grows indefinitely, and has no deletion path in v1.
- Discord nonce enforcement prevents duplicate action effects; a rare ordinary
  text duplicate remains possible in the accepted delayed acknowledgement
  window.
- Qualification resources contain private evidence and are retained until the
  operator explicitly authorizes disposal.
