## Implementation boundary

The active Dreamer is one `SessionMode.isolated` kernel one-shot. It receives
one host-generated `as_of` and one content-free maintenance input. Its exact
frozen plan contains only the existing bounded `Read` tools
`memory.search` and `memory.open`; its HostTable is empty. It has no external,
Web, Discord, filesystem, environment, MCP, native-Codex, connector, or `Write`
tool. Any native tool use or permission request remains fatal at the shared
provider boundary.

The closed `finish.result` contains only:

```text
insertions: at most 50 entries
  text: 1..8,000 characters
  source_memory_ids: 1..100 canonical UUID strings
remove_summary_ids: at most 100 canonical UUID strings
```

Extra properties are forbidden. The host consumes only the kernel-validated
authoritative terminal result. It never concatenates, parses, or executes
commentary `AgentText`. A dependency canary proves that a commentary-encoded
`memory.search` proposal cannot dispatch. A valid empty mutation batch is a
completed no-op.

Host code validates the entire batch before mutation: text and lineage bounds,
unmistakable-secret rejection, unique insertion text, unique canonicalized raw
lineages, existing raw sources, no summary-valued lineage, existing and
nonduplicated removal targets, no stale targets, and no conflict with an
unremoved summary's exact text or lineage. Any invalid member rejects the
whole batch. Accepted removals and insertions execute in one transaction.
Inserted summaries receive host UUIDs and one host timestamp with
`embedding = null`; only the existing bounded embedding backfill may later fill
that vector. Dreaming creates no `message` or `action` row and never changes or
deletes raw memory.

Groundedness is not claimed as a deterministic prose proof. The host proves
structural raw lineage; preservation of support, contradictions, and uncertainty
is a model contract measured by frozen recall and paid adversarial behavior.
Dreamer contract v3 additionally requires every multi-source summary to concern
one coherent matter or an explicit source-stated relationship. It forbids
grouping independent facts merely because retrieval exposed a generic category,
shared adjective, or coincidence; useful single-source summaries remain valid.

## Timer and manual dreaming

The service starts one ordinary in-process timer with a documented default of
86,400 seconds. It waits the full interval and never dreams immediately at
startup. Expiry marks one due pass; missed intervals do not queue. The normal
worker first drains delivery, controls, foreground owner work, and rememberer
work. It starts a Dreamer only when idle, under the existing process execution
mutex and deployment ownership lock, so only one provider turn or tool dispatch
is active globally.

An arriving owner input cancels or defers Dreamer reasoning and reads. Once the
short host mutation transaction starts, foreground work and shutdown wait for
its atomic boundary. Empty raw memory skips without admission or provider I/O.
Failure, cancellation, restart, or a missed timer is silent and creates no
durable job, notification, message, Discord output, or action.

`jarvis dream` performs one explicit stopped manual pass under the same
deployment lock and exact Dreamer. It refuses concurrent service ownership,
reports only mutation counts, and adds no command or Discord surface beyond the
operator CLI.

Deterministic verifier F passed the final-source timer tests for no startup run,
single-Dreamer exclusion, owner preemption, cancellation, restart, manual
invocation, zero-raw skip, and atomic-boundary waiting.

## Derived-memory rebuild

`jarvis rebuild-memory` is an explicit stopped operator command. It acquires the
existing deployment advisory lock, refuses a running service, and uses a
separate private rolling-admission journal. The production corpus is bounded at
10,000 raw rows and embedding calls are batched at at most 32 texts.

The rebuild sequence is linear:

1. Snapshot a length-delimited SHA-256 digest of every raw ID, exact text, and
   UTC creation time, excluding embeddings.
2. In one transaction delete every summary and clear every raw/summary vector.
3. Prove a raw simple-token lexical lookup immediately.
4. Re-embed every raw row.
5. Run exactly one bounded isolated Dreamer pass from raw memory.
6. Embed every regenerated summary.
7. Recheck the immutable raw snapshot after every destructive or model phase.

The stopped command never serves a mixed embedding space. Any exception exits
nonzero and does not restart the service; rerunning is safe because raw identity,
text, and creation time are immutable. A stopped production corpus rebuild uses
an exact root/serial-child admission ceiling of 11 turns, 225,537 input tokens,
and 32,385 output tokens including one-turn overshoot.

The release qualifier wraps the same corpus rebuild with the unchanged frozen
17-case evaluator before wipe and after regeneration. Its exact ceiling is 351
turns, 6,779,649 input tokens, and 854,913 output tokens. Each pre/post score is
atomically written as mode-0600
`recall-phase-evidence.json` in the fresh private runtime before later work can
continue. The file uses a temporary file, file `fsync`, atomic replace, and
directory `fsync`; it contains only bounded aggregate counts and per-case
selected/opened/search/overall pass booleans. It contains no usage, prompts,
provider/session IDs, memory text, or credentials. An injected post-score
failure test proves the pre score remains durable.

For post-rebuild evaluation only, S01 is rebound when exactly one regenerated
summary has the exact flattened raw lineage `{M11, M12}`. Zero or multiple
matches fail. Its UUID and text may differ from the seeded fixture; raw fixture
IDs remain exact. The original selected/opened/compact-result requirements are
applied to the regenerated identity. This is not a production alias and grants

per-case selected/opened/search/overall boolean.

## Accepted trade-offs

- Foreground recall remains mandatory before every owner-authored input. Cold
  recaller sessions add latency and paid tokens even for valid empty recall.
  In final A8 C, cycle-one recall used 3 turns, 37,264 input tokens, 286 output
  tokens, and 14,219 ms; cycle-two recall used 4 turns, 53,457 input tokens, 726
  output tokens, and 23,876 ms.
- Every stored memory, generated summary, and semantic query sent for embedding
  is disclosed to the metered OpenAI embedding endpoint under the
  embedding-only credential. Codex does not receive that credential, but the
  embedding provider necessarily receives the bounded text.
- Embedding failure does not invalidate a committed raw memory or summary.
  Nullable vectors preserve lexical availability during outages, so semantic
  recall may be temporarily incomplete until bounded backfill succeeds.
- Raw memory grows indefinitely and has no deletion, redaction, or forgetting
  path in v1. Summary deletion does not reduce the permanent substrate.
- Exact vector scans avoid unmeasured approximation loss but grow linearly with
  corpus size. No ANN service or index is added without measured need.
- Four GIN expression indexes preserve both stemming and exact-token behavior,
  while the unique lineage BTREE adds derived-write and storage cost.
- Canonical exact-lineage uniqueness prevents duplicate summaries and makes
  replacement unambiguous, but also forbids two distinct summaries over the
  exact same raw source set. A different facet requires a different source set
  or replacement of the existing derived row.
- Whole-batch validation and one transaction prevent partial consolidation,
  but one stale, secret-bearing, duplicate, or malformed mutation rejects every
  otherwise valid member of that run.
- Summary prose and UUIDs are disposable and need not reproduce seeded S01.
  Host lineage validation is structural only; groundedness and contradiction
  preservation remain stochastic evaluated model behavior, not deterministic
  semantic proof.
- Each timer, manual invocation, and rebuild runs one bounded Dreamer pass, so a
  large corpus may be summarized incrementally rather than exhaustively. The
  24-hour timer is process-local: it can drift under load and miss intervals
  during downtime; restart deliberately does not catch up and no durable job
  ledger or visible missed-run notice exists.
- Foreground owner work preempts Dreamer reasoning and reads, but once the short
  database transaction begins, owner work and shutdown may wait briefly to
  preserve atomicity.
- A rebuild requires service downtime and intentionally leaves the service
  stopped after interruption or failure. Derived state may be partially rebuilt
  while stopped; immutable raw memory makes an explicit rerun safe.
- The production stopped command and frozen release qualifier are separate
  operator surfaces: the former rebuilds an arbitrary real corpus, while the
  latter proves the version-controlled 17-case gate and evaluation-only S01
  binding on a fresh synthetic corpus.
- The private phase artifact omits provider usage, identities, traces, and
  prose so a crash-safe file cannot become a secondary sensitive transcript.
  Detailed paid metrics therefore still depend on sanitized final stdout.
- Paid recaller and Dreamer behavior is stochastic despite exact source,
  model, role, plan, schema, and dependency pins. Attempts A–AI are retained;
  there is no automatic retry and one final 17/17 run does not eliminate future
  variance.
- Fresh isolated roles and cold-bootstrap after compatibility change cost
  context and tokens. Local session-reference disposal does not prove deletion
  of provider-retained state.
- Qualification databases and runtime directories are retained until explicit
  cleanup so negative evidence survives. This increases temporary private
  storage and imposes a manual secure-disposal obligation.
- The inherited digest-pinned Linux image still installs Debian Git from the
  live package index, and `pip-audit` cannot map exact Git dependencies to PyPI
  advisories. Exact revision checks and full dependency suites compensate.
