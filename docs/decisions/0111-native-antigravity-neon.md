# adr 0111 · native antigravity for paid neon

**proposed design · november 26, 2026 utc.** target a single jarvis deployment. [adr 0110](0110-neon-quota-recovery.md) supplies the installed two-route baseline at `70522de`, database `0024`. this proposal changes paid main admission and adds one native backend. implementation and production activation are separate decisions. [installed cut](../issues/neon-combined-cutover.md)

## outcome and owner decisions

| order for new main turns | durable route id | harness and inference | admission |
|---|---|---|---|
| 1 | `personal` | codex, `gpt-6.2-astra/max` | existing personal included-usage rule |
| 2 | `agy_neon` | antigravity cli, `gemini-4-neon/high` | confirmed personal exhaustion, shared prepaid capacity, qualified agy opening |
| 3 | `google_neon` | existing stock codex, `gemini-4-neon/high` | same paid rule, agy safely unavailable for this opening |

the owner wants neon in google’s harness. agy wins ties against stock neon in the paired trial. bring concrete regressions or missing main capabilities back individually before adoption. both paid routes use the existing project, manual funding and data boundary. a primary outage, ambiguous allowance or elapsed reset timer does not permit new paid work. preserve 0110’s personal grace rule and original-route continuation exception.

the owner chose fresh native agy children. each starts from the parent’s task brief and the child’s own authorized workspace and tools. the parent includes the facts and constraints the child needs, with receipt references where relevant. copying the active parent session and carrying its tool history into a new child are outside the agy contract.

all existing main event types participate, including restricted scheduled workspace checks. keep current tool grants, approvals, stop, workspace access, evidence, receipts and public output. inferred shared summaries and dreams wait for personal capacity. out of scope are skid workers, nexus, embeddings, other models, generic failover, a route picker, separate google funding, extra retained agy transcripts, and a new archive or scheduler.

## b · admission, supervision and recovery

**owner and files.** `llm-agent-kernel/src/llm_agent_kernel/{definitions,provider,native,native_contract}.py` owns fit dispatch and the existing `run_native` supervisor. jarvis `kernel.py`, `definitions.py`, `native_protocol.py`, `native_runtime.py`, `native_journal.py`, `messages.py`, `native_failure_notice.py` and runtime composition in `cli.py` own policy and durable settlement. replace model-only role selection and partial provider rebinding with the whole selected backend binding. derive the workspace-check's tighter authority for that backend before acquisition. retain the exact check tool allowlist.

**opening algorithm.** extend the existing `choose_route(role, pinned?) → SelectedRoute | DeferredRoute` with route-local exclusions for this opening pass. keep serial admission. a pinned group considers its original route only. for a fresh paid group, check shared project evidence once, then consider agy and stock in order within that same group. distinguish a route-local pre-submission failure, definite input misfit, shared block, and possible submission. test each eligible route at most once per pass. a failed agy acquire cannot exclude the fresh group. use one frozen prefix, time, ordered inputs and receipt cut. reuse trailing-input peeling and workspace isolation. if the oldest indivisible input is too large for agy, test stock before parking it. a transiently unreachable larger route keeps work pending until fit can be established. oversized steers return to ordinary admission. qualify each route’s actual request bytes, token window, output reserve and rollover; agy documents up to 512k, stock targets 1,048,576. [model limits](https://antigravity.google/docs/models#gemini-4-neon)

| evidence | transition |
|---|---|
| agy preflight/acquire fails locally before possible input submission | select stock for that fresh group. re-evaluate order on the next opening |
| correlated definitive non-entry after arm | revoke the credential, close/join the tree, and positively prove zero upstream entries, native actions, callbacks and steers. fence and settle first. use the bounded fresh-retry allowance and skip the failed route for that admission |
| authenticated first-root funding refusal / project-wide throttle | gate both paid routes. retain origin, one durable shared probe per existing 60-second interval for depletion, retry-after for a shared throttle. personal recovery admits fresh work immediately |
| possible entry, dropped ACP stream, missing ack, owner stop | fence, settle original sealed output or reconcile every action, paid read, shell, child, input delivery and steer under existing authority. proven safe continuation keeps its original pin. unresolved effects park the affected group with one notice. honor stop/revocation before any new reasoning. keep independent work moving |

split the local adapter liveness test from `neon_paid_ready`’s project evidence. reuse the existing locked `neon_capacity` and `native_retry_after` records. an authenticated funding fact can stop later paid starts, independently of whether its original turn is safe to retry. preserve 0110’s durable pre-output acknowledgement and first-root refusal proof, including zero child, steer or earlier delivery; absence of ACP updates proves nothing. distinguish route-local failures from project-wide ones using authenticated scope. an unknown transport loss after dispatch never licenses a second opening for those inputs.

a restart pin selects the harness for a **new** attempt. follow existing `restart_reasoning`: after every original effect/delivery is accounted for, rebuild context from canonical inputs, receipts and authoritative outcomes, open a new agy session and deliver the new attempt once. never reload a dead session, replay its commands or invent signed parts. if the receipt state cannot support a safe new attempt, retain the hold. test clean recovery and missing evidence across process death with the agy directory gone.

**schemas.** in `jarvis-native-request.v5` bind the closed route, backend, qualified model/effort and definition fingerprint into the prepared digest. validate agreement with acquired endpoint, turn ref, seal and retry origin. reuse request/attempt, input delivery, invocation, action and trace records. retry keeps `{attempt_id, route, selection: fresh|pinned, ...existing evidence}`; route always names the originating attempt. keep `jarvis_home_message_v3`, the structured workspace result and existing approval format. keep database `0024`. new work has one executable contract.

**designer’s specimen and test.** “the draft was saved. i couldn’t confirm the calendar change.” require separate evidence for each clause. “queued until quota returns” fails for an ambiguous disconnect. inject loss after one synthetic write and before its reply, restart, and assert one executor entry, zero repeats, one notice and progress on an independent input. also prove primary exhaustion/reset/unknown, both single-host failures, shared depletion/refill, pinned versus fresh competition, agy-only misfit, a valid late seal, and stop during a child.

## c · composition, hard cut and proof

**owner and files.** deployment/integrator owns `codex_config.py`, `settings.py`, `native_cutover.py`, `session-compatibility.json`, dependency locks, `deploy/{install-contained-host,install-private-state,release-functions,cutover-hold,activate-release,verify-containment}`, systemd units and `docs/operations.md`. deploy a release-owned verified agy binary, separate uid, private socket, ephemeral home and isolated tool processes. the developer’s auto-updated executable remains an independent installation. remove the paid adapter's stock-only `PartOf` dependency and replace duplicated host inventories with one deployment-owned list. the optional hosts can stop independently; the shared paid service may take both paid routes offline.

mapping v8 extends v7 with `agy_neon {endpoint, host_user, host_home, binary}`. the enrolled shared paid origin, project and credential have one owner. manifest v6 binds route to backend, pinned binary version/digest, capability revision, qualified model/effort/context and child controls; retain personal role pins. retire the v7/v5 configuration loaders, v4 execution and two-route branches atomically. carry forward any active authenticated project-capacity hold and its next probe time. under named stopped custody, use the original release to inventory, settle or disposition all executable old attempts, sealed-but-unsettled products, due/waiting/pinned retries and parked work that could be released. verify the new release cannot dispatch any retired record. preserve immutable receipts, old route meanings, canonical history and unrelated operator holds. no compatibility mode or automatic rollback. [custody and recovery](0104-maintenance-without-owner-pause.md)

**designer’s specimen and test.** a redacted release receipt identifies binary/hash, expected and observed project/model/effort, route/attempt, disposition and evidence location. “service active” proves process liveness alone. rehearse the installed predecessor → target mapping, restore receipt, independent service loss, restricted and full capabilities and no secret/retained transcript after both crash and clean exit. distinguish paid live observations from injected quota/faults.

**sequence.** freeze contracts. each unit’s content designer owns a valid example, a plausible misleading example and a checkable rubric before red. start with a’s smallest live feasibility test. for each feature, run a temporary failing end-to-end test at its normal entry, implement, go green, simplify at the owning layer, and rerun on final pins. independent opus reviews each feature and combined evidence. compare both paid paths with the same synthetic task, tool receipts and rubric; record correctness, tool use, wall time and billed tokens where available. prefer agy on a tie. exercise all three choices through jarvis, including one live paid turn per harness. use macbook for detached rehearsals via dev-server’s rehearsal script. reopen and hash durable redacted evidence, report fixture cleanup separately, then delete only these temporary tests. stage a separately authorized stopped hard cut and verify installed linux containment and a synthetic journey through the ordinary entry. preserve the selected release on a failed pre-cut check.

**trade-offs.** a native harness avoids stock-to-google translation on route two but adds a second agent integration, a smaller context window and new containment work. one shared prepaid service limits spend administration and creates a common failure point. fresh children depend on the quality of the parent’s brief. child authority and effect recovery can still hold the cut. conservative recovery may leave one request waiting for its owner. a paired task can find a regression but cannot prove general superiority. pinning agy costs upgrade work; deleting the probes makes reproduction depend on the recorded pins, fixtures and receipts.
