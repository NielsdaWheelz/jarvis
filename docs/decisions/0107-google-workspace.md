## what the owner gets

| request | result |
| --- | --- |
| “what did the supplier say?” | normal jarvis chat on web or android. the subscribed main model reads the source, answers and states the scope and observation time. reads and answers enter ordinary history. reopening shows the dated answer. “check again” reads afresh. |
| “keep the second pdf” | one selected file goes to the existing private store and artifact viewer. no automatic incoming file saves. requested reports use the existing viewer. |
| “find the supplier’s emails” | fresh, pageable gmail results with sender, subject, date and ids where available. keep what was shown in ordinary history. |
| “a new email just arrived” | gmail marks incoming mail. jarvis checks the pending label every five minutes, including after downtime, and records each eligible visible message once. a message removed before observation can be missed. [live qualification](../issues/gmail-mcp-arrivals.md) |
| “draft a reply, change the address, then discard it” | create, list, read, replace and move drafts to trash on demand. replacement gets a new draft id. each action reports what gmail actually did. the owner sends in gmail. |
| “move the appointment” | jarvis can create, read, edit and delete events on demand, under the existing approval rules. identify the calendar, event, date and scope of a change before acting. |
| “check each friday for the supplier’s reply” | jarvis checks the authorized scope in the background. a match can send a generic phone alert. timing can reveal a match. a missed alert is acceptable. opening the alert requests fresh details. |

keep ordinary history, past and future. use existing chat and viewer. no separate mailbox index, calendar polling, direct mail sending, partner-only tools, other workspace products, new model, paid upgrade or workflow engine. public sending and in-place draft editing are unavailable to an ordinary project. [published tool tiers](https://developers.google.com/workspace/gmail/api/guides/quotas#gmail-mcp-toolsets) maps, oauth and phone push have separate purposes.
