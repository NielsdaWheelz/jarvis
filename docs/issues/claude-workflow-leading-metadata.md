# leading tracker metadata can block claude workflow discovery

in the v3 and v4 providers, `_claude_archive.files()` reads a workflow file’s first physical record to prove its original parent. native resume can move the file. a complete tracker row in that position makes enumeration fail for the whole profile. the folder and the tracker’s claimed session cannot establish parentage.

claude’s exit path can write agent tracking state separately. all 34 workers in the november 23 cohort start with a user message. on the mac, installed v3 listed a synthetic moved workflow under its original parent. inserting one v1 tracking row before the same sidechain header made public `archive_list` return `unsupported` for that home. the disposable fixture was removed. installed impact remains unknown. [metadata repair](../claude-data-flow-capture.md)

on november 24 the owner chose to retain the existing header contract for this recovery and track the lane-wide risk separately. a future change must prove that the actual first sidechain message still binds original session and agent across directory moves, contradictory or partial input fails explicitly, reads stay bounded, and internal workflows stay excluded.
