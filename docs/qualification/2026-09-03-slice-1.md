## Post-qualification correction — 2026-09-04

Revision `e9c84f1` closes a cancellation-publication race found after the live
qualification. The service previously signalled its published cancellation
token only after a separate asynchronous query reported an active input claim.
A pause arriving after token publication but before claim acquisition could
therefore miss cancellation. When more than one claim-sized batch preceded the
pause row, the first batch could reach a provider turn before checkpoint polling
observed the control.

The service now cancels whenever the published token exists. Claim state is not
part of the decision. The unused `has_active_claim` protocol, runner method,
checkpoint property, and test-double methods were removed.

The regression fixes the batch size at one, queues two ordinary owner messages,
pauses the runner after cancellation-token publication but before claim
acquisition, and then inserts `pause`. It proves the token is cancelled at the
claim boundary, the durable paused flag is true, and zero provider turns begin.

## Accepted implementation trade-offs

- Downtime catch-up is intentionally bounded to the newest configured page; an
  outage exceeding that bound skips the oldest overflow rather than creating an
  unbounded startup scan.
- An outbound delivery generation that exhausts its finite retries remains
  pending until the next startup or ingress signal. The fixed nonce prevents a
  recent accepted response from duplicating; Discord history cannot prove nonce
  identity indefinitely, so ADR 0022 retains the rare delayed ordinary-text
  duplicate risk. No action effect exists in Slice 1.
- Exact host controls are canonicalized to lowercase `stop`, `pause`, or
  `resume` before persistence. This intentionally discards only command casing
  and surrounding whitespace so Python and PostgreSQL classify the same row.
- Provider session history and references remain disposable acceleration state.
  Reconstruction may use more tokens and latency, but canonical messages remain
  authoritative.
- Admission recovery releases an orphaned concurrency slot without refunding
  its already charged rolling capacity, as required to avoid an unbounded
  crash-based quota bypass.
- The available dependency audit covers registry packages. Git-only dependency
  risk is instead bounded by exact pins, startup checks, and upstream suites.
- The qualification host is Darwin arm64. Linux service-manager and final v1
  multi-trial evidence remain separate final-acceptance work and are not claimed
  by this Slice 1 report.

No Gmail, Calendar, Maps, Web, memory behavior, action execution, approval, or
model-callable Discord tools were activated. Their later-slice absence is
intentional, not waived.
