### Read contracts

- `gmail.search` performs one `threads.list` call and returns at most 20 bounded
  thread ID/snippet records. It performs no hidden per-thread expansion.
- `gmail.read_thread` performs one `threads.get(format=full)` call, returns the
  newest bounded messages oldest-to-newest, prefers inline plain text, uses
  inert HTML only as fallback, and never fetches attachment bodies.
- Calendar list/get preserve normal and sparse-cancelled variants, nullable
  observed participant identity, aware instants, and deterministic IANA
  localization for offset-free provider times.
- A normal Calendar observed end is the required direct tagged union
  `TimedEventTime | AllDayEventTime | UnspecifiedEventEnd`. The unspecified
  branch is exactly `{"type":"unspecified"}` with no payload. A true Google
  `endTimeUnspecified` flag discards the compatibility `end` without parsing
  it; false or missing requires a valid known end. Future write inputs remain a
  separate two-branch concrete-end contract with address-required attendees.
- Places search/details expose bounded exact IDs and canonical `maps_uri`,
  normalizing the qualified Google link field.
- Directions requests one route, no alternatives and no polyline. It returns
  bounded distance, ceiling-rounded duration, description, and all required
  warnings. Departure-time restrictions fail before provider I/O.
- `web.search` uses the pinned Brave binding with
  `operation_deadline_seconds=12.0`; the selected grant allows one attempt.
- `web.read` uses `llm-tools-web-read-v2` with `plain-text-v2` and
  `html-visible-text-v2`, direct pinned-peer reads, bounded inert extraction,
  and SSRF, redirect, credential, media, and size rejection.

Stable identity values are never truncated. Oversized exact provider values
complete as declared `ProviderResponseTooLarge`; only explicitly
presentation-oriented Gmail snippets and bodies can carry truthful truncation.

### Calendar unspecified ends

observed three confirmed `fromGmail` events carrying Google's

## Accepted trade-offs

- V1 currently has one qualified local-account model. It has no model fallback
  if Terra retires or is unavailable; startup remains closed until another
  exact route is explicitly qualified. Provider model availability remains
  mutable despite exact dependency pins.
- Calendar translates Google's boolean-plus-placeholder representation into a
  direct tagged domain union and discards the placeholder. Consumers must
  handle a third observed-end variant and cannot use the compatibility value
  for display or duration inference. The live coverage gate also depends on at
  least three such events remaining inside the configured qualification window.
- The Calendar correction cold-bootstraps compatible Main sessions once. This
  gives the model the corrected schema rather than preserving a stale native
  session. It adds no database migration or action drain.
- Exact stable IDs and values fail as `ProviderResponseTooLarge` instead of
  being truncated. Gmail snippets and decoded body text may be explicitly
  shortened with truthful flags. Very large provider records can therefore
  fail instead of returning a misleading partial identity.
- Gmail search is one bounded `threads.list` request with snippet records only.
  Reading complete messages requires a later `threads.get`; this avoids hidden
  N+1 calls but may require another model step.
- Calendar observed participants may preserve both-null identity because
  provider emails are conditional. Future Calendar write attendees remain a
  separate address-required type.
- Place IDs use an explicit local 1,024-byte ceiling because Google documents no
  provider maximum. `maps_uri` hides current Google wire-name transitions.
- Directions returns one route, no alternatives, and no encoded polyline. This
  removes token-heavy data with no v1 language-model use but cannot compare
  alternate routes or render a map. Provider warnings remain mandatory output.
- Selectable plans forgo Brave's second attempt so a started `BilledOnce`
  search can finish inside the 12-second binding deadline before the 15-second
  executor fence. Transient search failure may surface sooner.
- A selected `web.read` is capped at 64 KiB and aggregate tool output at 256
  KiB. Large pages or compound observations fail boundedly rather than consume
  the definition's wider maximum envelope.
- Public search discloses the query to Brave; public read discloses the URL and
  host IP to the destination. The tools send no cookies or connector
  credentials and do not offer authenticated or JavaScript browsing.
- Read calls are serial and have no model-authored progress narration. Compound
  questions can take more turns and wall time in exchange for a linear,
  inspectable recorder and no parallel partial-effect state machine.
- The recorder is run-local. A `Read` with `BilledOnce` replay policy can be
  billed again after a process crash because its pre-crash observation is not
  durable; no action or uncertain write state is created.
- Rolling admission reserves worst-case turns and tokens before provider I/O.
  An unavailable usage report retains the complete reservation and can defer
  later work even when fewer tokens were probably consumed.
- Provider-runtime's full Linux suite runs in a digest-pinned container on the
  Darwin qualification host. Installing Git from the live Debian package index
  is a remaining reproducibility gap even though the base image, source commit,
  and project lock are exact.
- `pip-audit` cannot match the three Git dependencies to PyPI advisories. Exact
  commit verification and full upstream suites reduce but do not replace a
  Git-native vulnerability feed.
- The reused Discord role retains the owner-accepted inherited non-management
  permissions recorded in Slice 0/1. Discord remains outside the model catalog,
  and the host adapter suppresses mentions and embeds, but compromise of the
  bot token or host would expose that dormant authority.
- Discord's stable nonce deduplication is time-bounded and historical responses
  can omit nonce. A sufficiently delayed bounded retry can rarely repeat
  ordinary text; it cannot duplicate a model tool action because Slice 2 has no
  writes.
- Codex session history, compaction, and cache state remain disposable,
  non-canonical optimizations. Cold bootstrap can cost more, and deleting the
  local reference does not prove deletion of provider-retained session data.
