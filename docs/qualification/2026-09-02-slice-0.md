## Discord qualification

### Reused surface

- `discord.py` 2.7.1 for Gateway ingress, typing state, and interactions.
- Direct `httpx` REST v10 Create Message for `nonce` plus
  `enforce_nonce=true`; no private `discord.py` API.
- Exactly the `GUILDS`, `GUILD_MESSAGES`, and `MESSAGE_CONTENT` intents in the
  existing Gateway configuration.
- Existing registration, bot token, guild ID, owner ID, and channel ID.

Jarvis will re-author the adapter. Ariel additionally supports DMs, multiple
guild channels, slash commands, and broader interaction routing; those behaviors
are not reusable in v1.

### Live observations

- The token authenticated.
- The configured channel is a guild text channel in the configured guild.
- The first Create Message returned HTTP 200.
- Repeating the request with the same 20-character nonce and
  `enforce_nonce=true` returned HTTP 200 and the same message ID.
- The create response contained the nonce.
- `GET /channels/{channel}/messages/{message}` omitted the nonce.
- `GET /channels/{channel}/messages?around={message}&limit=5` omitted the nonce.
- Cleanup of each test message returned HTTP 204.

The live result falsifies ADR 0016's statement that bounded history exposes the
nonce. Discord documents `nonce` as optional on a Message object and only
promises recent uniqueness enforcement on Create Message. A delayed retry
cannot identify a historical message by nonce.

The current effective channel permission set includes the required view,
send, attach, and history permissions, but also reactions, embeds, invites,
mentions, application commands, public/private thread creation and sending,
polls, voice permissions, expressions, and external-app/media permissions.
Administrator and channel/message/webhook/role/thread management are absent.
This still fails the exact least-privilege contract.

The excess authority comes from the guild's `@everyone` role. The managed bot
role itself grants only view, send, and history; attach is currently inherited.
The bot has neither Manage Roles nor Manage Channels and cannot remove its own
managed or inherited grants. An owner-created channel member override must allow
the four required permissions and explicitly deny the rest.

Required change before sign-off:

1. Remove inherited permissions so the bot has only the four specified
   permissions in the configured channel.

ADR 0022 now records the owner's accepted correction: retain recent
enforced-nonce deduplication and explicitly accept a rare repeated ordinary
response after an ambiguous acknowledgement plus a delayed retry beyond
Discord's nonce window. Approval and external-effect identity remain independent
and cannot be duplicated by presentation. A2.9 therefore passes at the provider
boundary; its finite host retry/backoff proof gates Slice 1. A2.2 remains open
until permissions are reduced.

## Reconciliation and action recorder

### Bounded observation rule

External reconciliation performs reads immediately, after two seconds, and
after eight seconds. Each read has its own short timeout. Transient read failure
consumes that observation point and never proves absence. The action's immutable
`max_attempts = 2` remains a lifetime ceiling. At the ceiling, proved absence is
`failed`; unresolved evidence is `uncertain`.

### Gmail

- Create draft: derive the exact stable RFC `Message-ID` specified in SPEC
  section 5.5 from the draft-creation action ID; after
  ambiguity search drafts by that identity and fetch raw content. One exact
  match is success; complete absence may permit the one repeat; conflicting or
  multiple matches are uncertain.
- Update draft: preflight the expected digest. Desired content after ambiguity
  is success; the exact old content may permit one repeat; a third value is a
  conflict and is not overwritten. If the draft vanished, inspect Sent using
  the stable RFC identity.
- Send draft: preflight the complete approved snapshot. An exact Sent match is
  success. An unchanged exact draft plus no Sent match across the bounded
  sequence may permit one repeat only if the live qualification proves that
  condition safe. A missing draft with no Sent match is uncertain.

The stable draft RFC identity is now normative in SPEC sections 5.5 and 7.3;
without it, two identical draft actions could not be distinguished during
reconciliation.

### Calendar

- Create: derive the provider event ID from `action.id` exactly as SPEC section
  7.3 defines. Exact writable projection at that ID is success; 404 throughout
  may permit one repeat; a different or cancelled resource is a conflict.
- Update: require the expected snapshot/etag before one conditional update.
  Desired projection is success; the unchanged original may permit one repeat;
  any third state is conflict/uncertain.
- Delete: require the expected snapshot/etag before one conditional delete.
  404/cancelled is success; unchanged original may permit one repeat; changed
  live state is never deleted.

### Local schedule

- Create succeeds for recorder purposes when the immutable creation receipt is
  present, regardless of later product status.
- Receipt absence proves the local transaction did not finish and may permit
  readmission within the lifetime ceiling. Local schedule lifecycle never
  becomes uncertain.
- Cancel is its own action and position. Its atomic transaction writes its own
  receipt and the original wake's cancellation outcome. An unchanged queued
  original may permit one repeat; executing or terminal targets fail.

### Action-backed `llm-tools` recorder mapping

- `action.id` is both `InvocationPosition` and `EffectId`.
- `occupy` locks/reads the action and compares canonical tool ID,
  tool-contract/implementation/policy/plan revisions, replay policy, and
  canonical argument digest with the immutable execution contract.
- `reserve` records the exact frozen `Reservation`; action existence plus the
  execution contract is the durable occupied position.
- `dispatch_started` atomically requires remaining lifetime capacity, moves the
  eligible action to `executing`, and increments `attempts` immediately before
  handler entry.
- `dispatch_abandoned` is called only by the fenced reconciler after proof of
  absence and safety; it returns the position to an executable state without
  reducing attempts.
- `uncertain` is internal recorder recovery state. Product `uncertain` is set
  only after Jarvis exhausts reconciliation.
- `terminalize_and_settle` atomically stores the exact `ToolResult`, maps the
  product status, and settles the position-owned budget.
- Reconciliation may install an evidence-derived terminal result; later
  `occupy` replays it unchanged.
- For schedule create, a valid `result.creation_receipt` replays the original
  Success result even when the action's later product status is queued,
  executing, succeeded, cancelled, or failed. Wake execution changes only
  `wake_outcome`.

The library now exposes the required timeout state. The production Jarvis
adapter must pass the action/schedule recorder conformance fixture before Slice
5 exits and before any corresponding write plan becomes selectable.

## Expected provider-failure and cold-bootstrap matrix

The pinned kernel's deterministic conformance suite proves the kernel behavior
below. Jarvis still must qualify the durable host adapters and paid live route.

| Condition | Before any host-tool dispatch | After host-tool dispatch |
| --- | --- | --- |
| Missing, incompatible, or unresumable continuing ref while acquiring the session | Discard ref; one cold bootstrap at most | Not applicable to an already-dispatched turn; recover from durable action evidence |
| Provider quota exhausted | Host-authored stopped conclusion; consume input | No fallback or provider switch |
| Provider terminal expected failure after a turn starts | Host-authored stopped conclusion; consume input; no cold bootstrap | No cold bootstrap; durable action reconciliation |
| Native tool or permission event | Discard session; no model conclusion or host dispatch | Fail-stop; reconcile any independently committed effect |
| Invalid structured output | Bounded protocol correction in same run | No replay of a committed effect |
| Stale session-reference CAS | Configuration/ownership defect; no dispatch or settlement | Reconcile from canonical action state |
| Runtime invariant/configuration defect | Park input and open circuit for operator correction | Reconcile durable action; never blind retry |
| Process crash after ref advancement but before settlement | Discard speculative ref before reclaim/cold bootstrap | Do not replay action-lineage inputs; reconcile action |

No row permits a provider/model switch. No failure after dispatch receives a
fresh model attempt to recreate the same effect.
