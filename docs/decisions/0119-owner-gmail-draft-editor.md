# adr 0119. edit and send a jarvis draft in the viewer

[adr 0133](0133-viewer-approved-send.md) adds the exact send-review step and
owns the send request and shared approval interaction at the next cut.

**november 26, 2026.** jarvis writes a real gmail draft. its reply opens the draft in the requesting viewer. you read it, change recipients or files, and press **send** once. gmail owns the working copy. the conversation keeps what jarvis originally wrote. this amends [0105](0105-native-android.md), [0107](0107-google-workspace.md), [0115](0115-web-home-address.md) and the mail handoff in [0118](0118-chat-reading-and-approvals.md). implementation, provider qualification and activation have separate evidence.

## authority and scope

| actor | capability |
| --- | --- |
| jarvis | the existing agent-marked google connection creates and verifies a draft. chat, model tools, workers, scheduled work and generated pages receive no editor grant, save or send operation. |
| owner | the trusted private web shell may open, save and send one eligible draft through an independently enrolled standard gmail client. a deliberate send freezes the visible version. pausing cognition leaves this human interface available while the service runs. owner editor operations go through the editor receipt, without an agent action, conversational approval or agent write gate. |
| gmail | owns the current draft, stable draft id, changing message id and sent message. gmail can be edited independently. we accept a race after our last read. |

google documents separate clients for human and agent workflows and lists web mail clients as an approved use. this design applies that guidance to a handoff through a real gmail draft. the agent's public connector cannot edit in place or send. [client isolation](https://support.google.com/cloud/answer/15549257?hl=en) · [gmail policy](https://developers.google.com/workspace/workspace-api-user-data-developer-policy) · [tool availability](https://developers.google.com/workspace/gmail/api/guides/quotas#gmail-mcp-toolsets)

one account. live editing starts with verified jarvis creations under the new binding after cutover. one web editor serves desktop and mobile. android opens the private web route in a browser-bound custom tab, preserves its originating reply and returns on back. this can require browser sign-in. excluded features include a drafts folder, arbitrary gmail ids, native editor, alternate senders, rich-text authoring, gmail deletion, jarvis file browser, offline queue, automatic sent-mail search and new chat events from the editor. normal separately authorized gmail reads and existing arrival rules still operate.

## c. autosave and send

use prefix `/api/mail/{message_id}/draft/{create_action_id}`. resolve provenance, current grant and owner on each operation. the adapter calls fixed google oauth and gmail endpoints. no generic proxy.

| request | contract |
| --- | --- |
| GET | fresh current draft, or durable send disposition. return `{state,account,version,from,to,cc,bcc,subject,body,quote,threaded,files,as_drafted,reason?}` as applicable. mailbox = existing name/address pair. version = opaque binding to enrollment, draft, raw revision and local operation generation. existing file = {slot,name,type,bytes,sha256}. the server reports `as_drafted` only when the gmail message id and raw digest match the verified creation. representation-only drift may require review. status-only reads of a known sent/uncertain send need no mailbox search. |
| GET /files/{slot}?version=… | owner-opened current attachment. read the bound raw draft, validate version/slot/name/size/hash, then stream those exact decoded bytes. stale version returns 409. reuse the private original response’s no-store, nosniff and safe disposition policy. added device files can open from their local bytes. no persistent second copy. |
| PUT /operations/{uuid} | same-origin multipart, one json command `{kind:save\|send,base,to,cc,bcc,subject,body,files:[{keep:slot,sha256}\|{upload:index}]}` and ordered file parts for this device's new files. require one-to-one upload references, bounded lengths, exact retained slots from this base, valid decoded names/bytes and total serialized limits before entry. account, sender, google ids, thread, quoted suffix and credentials are server-owned. fixed part order in the final message. |
| GET /operations/{uuid} | retrieve the local disposition of this operation on this draft. return pending, saved with new version/slot map, sent with provider message id, definite failure, save unconfirmed, or send unconfirmed. a superseded operation may have expired. no dispatch on lookup. |
| POST /resolve-save | human decision after an uncertain save. bind old operation id and freshly reviewed remote version. only after the previous local sender has finished or died. retire that uncertainty, advance generation, return the current base. **use gmail version** discards local edits only on successful resolution. **reapply my edits** requires a new explicit save against this base, with owner-resolved file differences. never resolve an uncertain send here. |

use 200 for completed operations/equal replay, 202 for entered or unconfirmed with status, 404 for unrelated refs, 409 for stale base, held draft, changed uuid reuse or superseded operation, 410 for a known missing live draft, 413 for size, 422 for invalid/unrepresentable content, and a distinct reconnect-required state for unusable enrollment. return typed reasons. distinguish google permission denial, timeout and quota delay from draft deletion. GET performs zero mail writes.

**one durable row per touched gmail draft.** next migration after integrated head. key `(google_sub,draft_id)`. columns `generation bigint, operation_id uuid, kind, request_digest, base_revision, desired_digest, state, provider_result jsonb, updated_at`. constrain legal kind/state and unique operation id. kind is save or send. state is entered, saved, sent, failed, save_unknown or send_unknown. the generation-zero row has null operation fields. saved contains the confirmed message id, new version, ordered slots and confirmation basis. sent contains the accepted message id. entered, failed and uncertain rows can contain only an acknowledged id, a typed reason and retry delay as applicable. no body or file bytes. response digests use one versioned canonical encoding of envelope, body including quote, fixed reply data and ordered file descriptors with measured hashes. store the confirmed message id, revision digest and ordered slot identities for equal replay. gmail is the only persistent owner of the live body and editor uploads. private temporary files are reclaimed on success, failure and restart. address receipts within the authorized draft. a stale generation can never enter again. use the existing sql transaction and locked admission pattern. no transaction across google i/o.

serialize entry per draft across all tabs and callers. first hash kind, base, sanitized fields and ordered file identities including measured upload bytes (exclude multipart boundaries). check an equal uuid+command digest, then compare generation and fresh gmail revision, then commit a single entered operation under the row lock/CAS before network mutation. stale preflight cannot win admission. increment generation on claim. no transport write retry or automatic replay after timeout, token refresh or restart. keep in-flight work under service ownership across a lost browser connection. the single service holds its existing deployment ownership. before admitting home writes at startup, atomically convert leftover entered rows by kind to save_unknown/send_unknown. launch the google write and settlement in a service-owned task after durable admission, independently of the request coroutine and its cancellation. during runtime only its owning live task can settle the claim. resolve-save first proves no such task remains. a crash after claim can leave a false uncertainty. this costs availability to prevent a duplicate send. settle only the matching generation/uuid. a save sends one same-id update. read back and compare the desired semantic content before saying **saved in gmail**. following a lost reply, a matching read proves the desired state exists, not which request caused it. otherwise show both versions and offer explicit resolution. a delayed external write may still land. negative reads alone cannot prove failure. an acknowledged but unverifiable change remains visible as such.

send the actual draft id, thread id when applicable, and final reviewed mime together through gmail's draft-send endpoint. include unsaved edits and newly added files. one click is sufficient. a positive message receipt means gmail accepted the send. a gmail 404 for a previously verified eligible draft means gmail reported it unavailable. it proves neither deletion nor sending. an entered or uncertain send blocks further mutations of the same draft across devices, re-enrollment and restart. show **send unconfirmed · check sent mail** with an account-specific link to gmail sent. keep the last receipt even after checking. no automatic retry, mailbox search, agent dispatch or “mark as failed” escape. a definitive rejection before effect permits correction. keep oauth refresh separate from mutation retry. use a random editor epoch, captured with the signed workspace subject in the immutable create claim and distinct from either oauth grant id. the stopped enrollment generates it. the human grant and epoch live in private application-owned state outside both backup sets. ordinary same-subject reconnect retains the epoch and receipt fence. every supported restore, including in-place db-only restore, stops the service and runs `owner-gmail-invalidate-restore` before opening restored state. the command durably clears the epoch before disconnecting the grant. restored source verification rejects a present epoch. only stopped enrollment from absent or invalidated state generates a new epoch for the same subject. a copied bare database cannot enable writes. require a matching epoch for every live action. pre-restore links then remain inspectable only. the owner selected the stopped restoration procedure. a database replacement outside that procedure has no automatic rollback detector. exercise both restored-host and in-place recovery. ## d. interaction

open on the verified recipients, subject, body and ordered files. show from, to, cc, bcc, including populated bcc at review. attach from the device picker. remove by slot. no upload to jarvis originals. debounce valid edits for one second, or five seconds when aggregate attachment data exceeds 5,000,000 bytes. these are initial interaction settings. gmail replaces the entire message on each save, even for one character. larger drafts therefore transfer more data and appear later on another device. one mutation in flight per editor. invalid or partially typed addresses stay visible locally and block send. allow incomplete drafting locally, and save valid representable envelopes. send needs a valid recipient across to/cc/bcc. a fresh read and actual provider support govern empty-recipient autosave. on send, bypass the debounce, finish an in-flight save, rebase only the verified equivalent local version and submit the exact clicked contents once. never send after a conflict or ambiguous save without renewed review. map returned slots to the originating file identities. late acknowledgements cannot remove newer typing/files or steal focus.

a refresh, tab closure or killed phone may lose unconfirmed edits and file bytes. the owner chose memory-only working state. use the normal dirty-leave prompt where supported. no background send, durable browser copy or claimed offline save. reuse the shell’s file selection, hashing and accessibility primitives without coupling editor changes to chat submission, r2 custody or chat draft persistence. quiet acknowledged saves, actionable failures. show “changes only on this device” while offline, “this draft changed in gmail” with both versions on conflict, and the exact failed file or field. preserve typing through recoverable failures while the document remains open. cross-device continuation starts at the last gmail-confirmed revision. responsive labeled controls, keyboard navigation, accessible status, 320px and large text without sideways page scroll. send stays reachable above/after the phone keyboard. enter in the body adds a newline.
