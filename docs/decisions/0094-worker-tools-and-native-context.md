# adr 0094. worker tools and long native turns

accepted amendment to [adr 0086](0086-native-recovery-and-memory-availability.md). the predecessor is the committed adr 0093 candidate `b60eb74`, schema `0018`, stock `0.171.0`. the [roadmap](../implementation-plan.md) owns sequencing.

## product decisions

jarvis chooses its procedure. the host makes an operation's result durable and truthful. a worker finding, an idle terminal and a model failure are evidence jarvis can use. jarvis decides what they mean, whether more work helps and what to say in web chat.

| situation | target behavior and trade-off |
| --- | --- |
| delegation | use the existing skid-backed tools. a chosen wait survives restart. a launch can survive a crash before a separate wait is registered. accept that gap. a universal completion callback, worker report format or delivery obligation would change the product. |
| a long, healthy turn | stock codex compacts its working history and continues on the same native thread. compaction costs inference and can lose detail. originals remain available when detail matters. |
| actual terminal context exhaustion | give jarvis one fresh look at existing evidence. jarvis resumes useful work or explains the blocker. the fresh look can cost a model turn even when nothing useful survived. |

### a. worker control

keep the current contracts. `agent.start` creates a terminal and optionally writes a brief. `agent.send` writes to a captured terminal. `agent.read` returns bounded terminal text with its scope. `agent.wait(target, state, timeout_seconds, maxBytes)` registers an observation and returns immediately. its receipt fixes the target and deadline. first match, timeout, cancellation, replacement or unavailability publishes one causal host event. `agent.cancel_wait` ends the observation. main can handle the event after the originating turn ends. the timeout governs this particular observation. worker output is ordinary text or files. [tool schemas and watcher](../worker-launch-observation.md#capability-and-api)

there is no worker api or schema delta. retain the separate launch, delivery, observation and task facts. after a crash, recover the original dispatch receipt. an unknown write stays uncertain. if no wait was registered, the host creates none. jarvis may inspect the worker on a subsequent turn. the private web home handles any ordinary reply jarvis chooses. related messages in the opening carry `delivery=context_only` and their historical `message_id`. only delivered input blocks supply `input_id` for dispositions. [observed crash gap](../issues/native-protocol-diagnostics.md) · [restart and subsequent handling](../delegated-follow-through.md#implementation-evidence--2026-11-15)

**content designer.** give jarvis an ordinary investigation with a delayed, independently checkable finding. good content answers the question from available evidence. distinguish an expired watch from a failed task, or an opened terminal from a delivered brief. silence after a superseding stop can be appropriate. judge the brief and any chat response in context.

### b. native context

main has no cumulative jarvis token quota. stock checks context between model calls and can compact before continuing. a large new input can cross the model window in one step, and compaction itself can fail. a separate stock admission limit applies before inference. the november 18 context failure and the 2.33-million-character opening rejected at admission were different incidents. jarvis already fits submissions and pages original receipts. the records do not establish whether compaction ran on the failed historical turn. [turn loop](https://github.com/openai/codex/blob/ccf9be8cc458bd6b8336fe84d68d8893f2691a5e/codex-rs/core/src/session/turn.rs#L720-L814) · [installed context failure](../runtime-reliability-and-integration.md#installed-accounting-and-context-exhaustion) · [opening repair](0086-native-recovery-and-memory-availability.md)

1. **provider.** map a matching failed `turn/completed` with `turn.error.codexErrorInfo == "contextWindowExceeded"` to `AgentFailure("context_window_exceeded")`. extend the closed cause and verify its codec round-trip. preserve quota and protocol-conflict precedence. intermediate errors, usage counts, prose and rejected openings cannot select this cause. the kernel carries the original seal. [stock error shape](https://github.com/openai/codex/blob/ccf9be8cc458bd6b8336fe84d68d8893f2691a5e/codex-rs/app-server-protocol/schema/typescript/v2/TurnError.ts) · [stock failed-turn emission](https://github.com/openai/codex/blob/ccf9be8cc458bd6b8336fe84d68d8893f2691a5e/codex-rs/app-server/src/bespoke_event_handling.rs#L1588-L1607)
2. **jarvis.** use shared live/startup seal settlement. under the conversation lock skip settled attempts and select only `was_waking AND proven_native_delivery` for this attempt. zero matches means zero charges. retain scope, newer-control, supersession, park and operator-release checks. settle the original seal with `product_outcome.reason=context_window_exceeded`. consume `recovery_pending` once in that transaction. for each eligible input, set an unused `native_retry_after` to database time plus 30 seconds and mark `message.trace.native_context_retry=true`. a spent slot parks the input with one repair notice naming the actual last failure. if this attempt's contact loss already consumed the flag, its late seal may only mark its still-eligible outstanding retry as context exhaustion. preserve the deadline and publish no second notice. a late generic failed or cancelled seal after the same contact-loss charge keeps its generic failure outcome and leaves the scheduled retry alone. protocol conflicts still take precedence. return eligibility changes to the service loop.
3. **fresh opening.** name each due input's last failure in host framing. a marked input says its work hit the context limit and original receipts can be paged. an unmarked retry says that work lost contact with the model. preserve owner text, controls, approvals, unknown effects and receipt inventory. jarvis judges what evidence to reopen, whether to continue and how to explain a blocker. clear the marker wherever the retry timestamp clears, including a named disposition, owner stop or operator release. omission leaves the allowance spent. loss and exhaustion share one chance between dispositions, so a mixed pair can reach operator repair. [existing per-input rules](0086-native-recovery-and-memory-availability.md#b-native-admission-rejection-and-one-fresh-retry)

if the fresh opening itself is too large, keep the measured singleton park. inspect `fit_native_inputs` and `native_receipt_context` for repeated related text and action arguments. change the projector only for reproduced waste while preserving exact operative facts.

**content designer.** use a fixed 73-item review, a duplicate and an uncertain previous write. a good continuation preserves the finding and picks up what remains. in the blocked variant, receipts cover 1–39 and 41, and the next source is unavailable. an accurate answer identifies the gap at 40 and leaves the write uncertain. the model judges progress. no checkpoint api, progress score, second compactor or model-size change.

## qualification

on 2026-11-20, opus 5.5 signed off on design, red, green, refactor and live evidence. the tested runtime was jarvis `e5c6910`, provider `76a95bd`, kernel `ed5b1e9`, and authenticated stock `0.171.0`. exact dependency objects are in verified local git bundles. the macbook evidence index `qualification/adr0094/acceptance.json` reopened at sha256 `908c641b564ca7c16758d7acb06317482d19e8583fad0fd032d2444b3ecc2651`.

- real stock against a controlled backend emitted the typed context failure. the predecessor lost the cause. the final codec, precedence controls and exact kernel seal passed. real postgres proved the per-input deadline, both crash edges, late seals and one notice after a spent retry. the retained capture/retry regression passed.
- on macbook, a controlled lower threshold produced a real compaction and a correct later answer within one stock turn. separate runs used a controlled failed seal and a live fresh model. web chat verified all 73 records in one run and reported the gap at 40 in the blocked run. the original uncertain action remained byte-identical with one entry. the blocked rerun used a grader that recognizes “unresolved” after the first grader rejected that wording.
- three live worker journeys passed through skid and real restarts. the completed and pending-parent runs used slightly different owner wording from the predecessor. in both, one registered wait produced one event and evidence-backed web handling. a still-pending parent retains its ordinary due turn and jarvis can speak on that later turn. a confirmed launch without a wait recovered its original receipt with one entry and no registered watch.
- scoped probes and fixtures were removed. [one clean setup checkout](../issues/adr0094-rehearsal-checkout-hold.md) remains under a virtualization read hold. the optional linux fixture failed during setup and was cleaned. installed acceptance remains a separate cut.
