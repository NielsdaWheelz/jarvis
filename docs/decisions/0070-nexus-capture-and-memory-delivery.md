# adr 0070: nexus capture and memory delivery

status: accepted and implemented source, 2026-11-14; isolated functional proof
recorded in [current evidence](../universal-memory.md#memory-completion-source-qualification).
the [native rollout source qualification](../universal-memory.md#native-memory-rollout-source-qualification)
resolves the dependency audit under adr 0072. online installed qualification passes
with its named profile deferrals;
nexus installation is deferred to its next release.

## authority and evidence

the owner approved completing the existing universal-memory system and its live
integration, adding nexus conversation capture to this delivery, and deferring
the broader usefulness/realistic-load comparison to a later pr. the owner then
selected future activity only; one-time capture without version/update/delete
synchronization; durable conversation/evidence rather than transient tool bodies;
and a durable pending export that survives nexus deletion until acknowledged.
historical import and backup/restore remain deferred. the initial instruction
authorized docs; the subsequent owner instruction authorizes full source work
and temporary red/green/refactor proof in isolated worktrees. installed activation
remains separate.

current nexus source has one account-owned librarian transcript, immutable
question/answer pairs, failed/cancelled retries as new turns, and physical
terminal-turn deletion. its sole terminal fold is the appropriate local commit
boundary. polling deletable messages would lose evidence during an outage.
the prior send/rerun/regenerate and private-build-secret handoffs are stale.
the pre-delivery compactor omitted its accepted editorial ordering and initial
numeric byte target; the implementation repairs both through the existing role
and shared target constant.

## decision

retain the standalone postgres memory library, archive/tree/view, independent
search, common policy and jarvis hosting. add the narrow nexus source contract
in [memory delivery](../memory-delivery.md), which owns its exact schema, api,
publication, content and verification requirements. the
[roadmap](../implementation-plan.md#memory-delivery) remains the single delivery
sequence; the consolidated [memory contract](../universal-memory.md) owns the
unchanged core.

nexus commits an immutable source snapshot with each eligible terminal
turn. eligibility is stamped at new run admission; old runs are never backfilled.
central archive/leaf/progress commit precedes acknowledgement; only verified
acknowledgement permits removal of the pending export. later nexus deletion,
correction, retry or undo does not modify captured history. preserve the actual
retry link and outcome, not an invented version/branch system. capture is
host-owned and confers no model tool or new external-effect authority.

qualify every current memory api/mcp operation and actual jarvis/native/nexus
composition through bounded end-to-end integration and live journeys. keep
transactional, attribution, authorization and recovery checks in this delivery.
defer load scaling, comparative memory algorithms and broad usefulness evaluation.
each feature has a content designer and an independent adversarial reviewer at
design, red, green, refactor and cleanup. delete newly introduced temporary
tests/probes after final proof; preserve pre-existing authorized checks.

hard-cut replaced source/configuration paths. retain existing canonical data and
original recovery obligations; add no legacy reader, fallback or parallel runtime.

## supersession, costs and acceptance

this supersedes adr 0067's exclusion of nexus capture and its retired chat-route
description, and the affected lane/schema/publication and per-feature review
clauses in the memory contract. native capture rules and the sixteen existing
native/jarvis lanes remain. the explicit nexus source is additional; nexus note
and read provenance remain distinct from native profiles.

costs: one temporary source-owned export store, additional compression/storage,
eventual capture after terminal settlement, and permanent retained copies after
nexus deletion. capture outages accumulate pending exports; a rejected export
requires visible operator repair, never silent loss or repeated generation.
background capture receives narrowly scoped upload authority. archive loss on
host failure remains possible while backup is deferred. deleting new temporary
checks leaves less retained regression coverage; the owner selected that workflow.

implementation must prove the delivery contract's acceptance matrix, including
outage plus deletion, lost acknowledgements, future-only admission, exact source
attribution and all supported live memory clients. documentation/static success
does not establish any of those behaviors. production activation remains separate.
